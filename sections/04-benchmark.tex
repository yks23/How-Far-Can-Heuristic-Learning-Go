\subsection{Rules and Arena Definition}
\label{sec:arena-formulation}

An arena instance is the tuple $(G,R,A,F,H)$: a game $G$, fixed rules $R$,
role-specific action space $A$, referee $F$, and archived human field $H$.
A policy reads its role's visible state and returns a legal action; the referee executes
the match and returns its outcome and replay. At each round, AHL receives $(R,A)$, the
current program, and training replays, then outputs a revised program that persists
across rounds.

\benchname is an archive-backed arena of \val{ngames} competitive games. Each game
provides fixed rules, a machine-readable action space, a runnable referee, and
human-written programs (\val{nsubv} archived versions). We use one uniform evaluator
for both the archived programs and our methods.

and asymmetric games, so we make no stronger game assumption. Each game ships a
legality specification and referee contract, making both sides auditable.

\subsection{Task Suite and Provenance}
\label{sec:arena-provenance}

The arena originates from a classic game competition organized by students at leading
universities and held for several decades. We consolidate its historical rules,
backends, frontends, and player submissions, and select nine representative games as
the \benchname suite. Per-game rules, action spaces, and replay formats are given in
Appendix~\ref{app:arena}; Appendix~\ref{app:case} works through one game in full.

The sample emphasizes three properties: \textbf{breadth}, covering game forms familiar
to a broad population of participants; \textbf{classicism}, grounded in a competition
with a multi-decade history; and \textbf{diversity}, spanning grid and territory games,
survival, hidden identity, asymmetric roles, and scripted reasoning so that conclusions
do not depend on one game mechanism.

\subsection{Archive and Submissions}
\label{sec:arena-archive}

Each submission is a versioned source snapshot with a manifest row. We report versions,
not people: identities are incomplete and versions are correlated, so percentiles state
their unit of independence. Only playable snapshots enter the opponent pools, and the
archive's development/held-out split is retained.

The version index provides a common revision count for human maintenance; its
distribution and caveats appear in Appendix~\ref{app:human}.

The ranked field is a finalist subset and archive ratings are used only for provenance;
we recompute all ratings and program-size measurements under our uniform contracts.

\subsection{Match Evaluation Protocol}
\label{sec:arena-eval}

All games use one referee interface: a seeded request fixes the programs and roles, and
the referee returns scores, a winner, and a replay. Code runs in a sandbox; asymmetric
roles are evaluated in paired swapped orders.

Match success is determined by the referee's final result: an illegal move, timeout,
or crash is a loss for that player, while infrastructure failures are rerun and do not
count toward player results.

The replay records each role's visible state at every step, legal action set, selected
action, and whether it was accepted, without exposing hidden state. This is the training
trace consumed by AHL; its concrete format is given in Appendix~\ref{app:case}.

\subsection{Leaderboard Scores}

For each match, the winner receives $S=1$ and the loser $S=0$; if the referee returns a
draw, both receive
$S=1/2$. Given current ratings $r_i,r_j$, player $i$'s expected score is
\[
E_i=\frac{1}{1+10^{(r_j-r_i)/400}},
\qquad r_i' = r_i + K(S_i-E_i),
\]
where $K$ is fixed in advance. The leaderboard score is the final Elo after all matches
against the specified opponent set; the AHL agent never reads this score during training,
and Elo is used only as a post-training evaluation metric.
